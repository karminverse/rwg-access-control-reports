### reUSD -- touches: collateral valuation / mint inflation -> WATCH

**This is the one item to carry forward.** Two distinct things happened; only the first
reaches the collateral DOLA lenders hold.

**(1) The senior collateral's NAV feed was migrated -- SENIOR, not junior.**
The share price FiRM uses to value reUSD is written by a NAV consumer contract that holds
the sole price-setter role on the share-price calculator. This period a new adapter
contract was granted that consumer's EMERGENCY_UPDATER role, the legacy daily trigger was
switched off, and the live price is now produced by a Chainlink CRE oracle network. The
cutover was staged across the window (adapter authorized at block 25,646,462; old trigger
disabled at 25,661,508; first CRE-driven price at 25,663,397).

- **The new authority is a machine, not a person.** The adapter was re-derived from
  bytecode (it has no verified source). Its 618-byte body contains no storage reads or
  writes, no owner, no proxy pointer, no upgrade path and no self-destruct. The single
  address it accepts calls from, the single contract it writes to, and the function it
  calls are burned in as bytecode constants -- it cannot be repointed or taken over. **No
  human key gained NAV-write access this period**; the only role change was this contract
  being added.
- **The old 10% deviation guard no longer binds the live path.** Routine prices now enter
  through the emergency-write entry point, which by design skips that check; the guard
  remains configured but is dead code on the retired path. **It should not be cited as a
  live protection in this or future reports.**
- **What replaced it is materially stronger.** The new oracle core enforces a 0.50% band
  per automated write (vs 10%), a 2%-per-14-day cumulative velocity limit, up-or-flat
  monotonicity, a hard absolute price ceiling that did not previously exist, and a 36-hour
  staleness window; reports are verified against a **4-of-10 signature quorum** and bound
  to a single authorized workflow identity. Against a faulty or captured feed this is
  roughly **20x tighter per write and ~70x tighter sustained** than the arrangement it
  replaced.
- **Price continuity across the cutover is clean.** The first post-migration write landed
  at 1.092631e18 against 1.091317e18 before -- **+0.120% for the week**, matching the
  pre-migration accrual rate, with seven gapless daily ticks and no discontinuity.
- **Two genuinely new fragilities, both in the stale-price direction:** the automated path
  can only move price up or flat, so a real impairment would need a discretionary, delayed
  markdown to be reflected; and the downstream push is a best-effort call whose failure is
  swallowed, so a write landing inside the shared 4-hour window can leave the lender-facing
  price stale-high until manually resynced.
- **Important context so this is not misread as a new risk:** the reUSD 3-of-5 Safe can
  write an arbitrary price into the calculator in one transaction with no delay and no
  deviation cap, once per 4 hours. **That was equally true before this period** (since well
  before the baseline) and did not change here. The new machine rails constrain the oracle,
  not that Safe.
- The scanner's role-mapping was degraded for two of the new contracts on this path
  (source and ABI unavailable); they were identified from bytecode during verification. The
  full control chain is four report providers feeding two oracle cores.
  - verified: role-grant event at block 25,646,462; trigger disabled at 25,661,508; live
    writes at 25,663,397 and 25,670,569 traced end-to-end from transmitter through
    forwarder, provider, core and adapter to the calculator; full role-holder replay from
    contract genesis against the baseline; oracle rails read live; adapter disassembled.
    Adversarially re-derived twice from independent angles. (2026-08-03)
