### reUSD | mint inflation (NAV valuation path) | WATCH

**This is the one item to carry forward.** reUSD is still in assessment and has no live
FiRM market, so nothing here is live lender exposure. It is tracked because the NAV feed
is central to whether the asset is suitable. Two distinct things happened this period, and
only the first touches reUSD's own valuation path.

**1. The senior-tranche NAV feed was migrated. Senior, not junior.**

reUSD's senior share price is written by a NAV consumer contract that holds the sole
price-setter role on the share-price calculator. This period a new adapter
contract was granted that consumer's EMERGENCY_UPDATER role, the legacy daily trigger was
switched off, and the live price is now produced by a Chainlink CRE oracle network. The
cutover was staged across the window: adapter authorized at block 25,646,462, old trigger
disabled at 25,661,508, first CRE-driven price at 25,663,397.

- **The new authority is a machine, not a person.** The adapter was re-derived from
  bytecode because it has no verified source. Its 618-byte body contains no storage reads
  or writes, no owner, no proxy pointer, no upgrade path and no self-destruct. The single
  address it accepts calls from, the single contract it writes to, and the function it
  calls are all burned in as bytecode constants, so it cannot be repointed or taken over.
  **No human key gained NAV-write access this period.** The only role change was this
  contract being added.
- **The old 10% deviation guard no longer binds the live path.** Routine prices now enter
  through the emergency-write entry point, which by design skips that check. The guard
  remains configured but is dead code on the retired path. **It should not be cited as a
  live protection in this or any future report.**
- **What replaced it is materially stronger.** The new oracle core enforces a 0.50% band
  per automated write (against 10% before), a 2%-per-14-day cumulative velocity limit,
  up-or-flat monotonicity, a hard absolute price ceiling that did not previously exist, and
  a 36-hour staleness window. Reports are verified against a **4-of-10 signature quorum**
  and bound to a single authorized workflow identity. Against a faulty or captured feed
  this is roughly **20x tighter per write and about 70x tighter sustained** than the
  arrangement it replaced.
- **Price continuity across the cutover is clean.** The first post-migration write landed
  at 1.092631e18 against 1.091317e18 before it, so **+0.120% for the week**, matching the
  pre-migration accrual rate, across seven gapless daily ticks with no discontinuity.
- **Two genuinely new fragilities, both in the stale-price direction.** The automated path
  can only move price up or flat, so a real impairment would need a discretionary, delayed
  markdown to be reflected. And the downstream push is a best-effort call whose failure is
  swallowed, so a write landing inside the shared 4-hour window can leave the published
  share price stale-high until it is manually resynced.
- **Context, so this is not misread as a new risk.** The reUSD 3-of-5 Safe can write an
  arbitrary price into the calculator in one transaction, with no delay and no deviation
  cap, once every 4 hours. **That was equally true before this period**, well before the
  baseline, and did not change here. The new machine rails constrain the oracle, not that
  Safe.
- **Monitoring coverage of the new path.** The full control chain is four report providers
  feeding two oracle cores. Role-mapping was degraded for two of the new contracts (source
  and ABI unavailable); both were identified from bytecode during verification. The two
  oracle cores that now hold those limits are recorded only as pointer targets, not scanned
  contracts, so changes to the limits themselves would not surface. **A repoint to a
  different core would still be caught.**

> Verified: role-grant event at block 25,646,462; trigger disabled at 25,661,508; live
> writes at 25,663,397 and 25,670,569 traced end to end from transmitter through forwarder,
> provider, core and adapter to the calculator; full role-holder replay from contract
> genesis against the baseline; oracle rails read live; adapter disassembled. Adversarially
> re-derived twice from independent angles. (2026-08-03)
